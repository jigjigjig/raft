# Otari Games submission — Raft

This is the submission text as posted; the living record is [`otari-log.md`](otari-log.md).

**My project's title:** Raft

**What it does:** Raft turns a pile of LLM traces into a research dataset you can question in plain English. You type "which failure mode costs me the most?" or "what do my users struggle with?" and Raft decides how to answer: it compiles the question into a typed query, routes it down one of three paths (recorded columns → parameterised SQL; open-ended → emergent clustering with no shipped taxonomy; genuinely new → it writes a per-trace question, asks your approval and evaluates it over every conversation), computes every number with code you can read, and links every number back to the exact conversations it came from. Nothing is precomputed for a fixed list of questions. Every quote is a verified literal substring of a redacted trace; PII never reaches a model; every answer leads with what is disproportionate rather than what is biggest. The LLM work — planning, aspect evaluation, cluster naming, autopsies — runs exclusively through Otari across six model roles, each on an open-weights model.

**Repo / code:** https://github.com/jigjigjig/raft

**Web URL:** https://raft-production.up.railway.app

**Documentation:** Full feature log with request IDs, wire-level errors and measurements: https://github.com/jigjigjig/raft/blob/main/otari-log.md. Condensed version below, one entry per feature. Everything stated as observed was observed against hosted Otari (api.otari.ai); everything not observed is marked as such.

**Live runs:** 24 Aug — planner `openai/gpt-oss-120b` 41 ok / 2 failed, 2.6 s avg · aspect evaluator `Qwen3-30B-A3B-Instruct-2507` 1,683 ok / 11 failed · cluster namer `Hermes-4-70B` 21 ok / 4 failed; one full evaluation over 847 conversations in 188 s for $0.059. 4 Sep (submission day) — all six roles completed live with request IDs, and the flagship question "How many people are getting product suggestions?" was proven end to end: 847 of 847 judged by Qwen3-30B, zero rows by any local fallback, 847 of 847 evidence quotes verified as literal substrings, $0.059.

- **Routing** — I've used Routing to run six role-specific model tiers behind one base URL and one credential. I found role assignment, provider abstraction and final-model reporting easy: swapping a 30B for a 70B for a whole role is a one-line YAML edit, and the response's own `model` field lets Raft show which model really answered. I struggled with catalog trust, deployment-dependent paths, unnormalised parameters, unadvertised latency and a vanishing model, because a catalog id is not proof a key can reach it; because management routes live at `/v1/models` on standalone and `/api/v1/models` on hosted; because parameter incompatibility arrives as an undifferentiated HTTP 400 (`temperature` "deprecated for this model"), so I wrote a retry-minus-one-parameter loop; because same-size models differ 4–9x in latency (Hermes-4-405B 3.4–4.0 s vs Llama-3.3-70B 16.8–32.6 s on the identical naming payload) with nothing in the API to hint it; and because `Hermes-4-70B`, which answered 21 calls on 24 Aug, returned `404 The model does not exist` on 4 Sep — removed from the catalog with no notice, killing two roles until a preflight check found it. Otari never rerouted a request for us, so Raft now walks its own `[primary, fallbacks]` list on a "does not exist" 404 and records it. One more gateway quirk: it echoes `"model": "Qwen/…"` for a request that named `mzai:Qwen/…`, which a literal comparison read as a reroute for a whole evening.

- **Guardrails** — I've used Guardrails to add a prompt-injection checkpoint over untrusted trace text before it reaches a model. I found the request shape easy: one `guardrails: [{profile, mode: "block"}]` array on the chat body I was already sending. I struggled with the failure mode, because hosted Otari answers `502 guardrail profile 'prompt-injection' requested but no guardrails service is configured` and fails the **entire** completion rather than the optional layer, a 502 cannot be told apart from "temporarily down", and I never once saw a successful verdict — so I still don't know what a pass or a block looks like on the wire. Raft drops the guardrail block, retries once, and records the feature as unavailable.

- **MCP Servers** — I've used MCP Servers to give the planner read-only access to Raft's redacted trace table. I found the wiring easy: `mcp_server_ids` is one more field on the chat body, and exposing five read-only tools took a 154-line JSON-RPC endpoint with no MCP library. I struggled with reachability, out-of-band registration and unobservable tool use, because the server must be publicly reachable (a product on localhost cannot use the feature at all), because registration happens outside the request that uses it, and because the response says nothing about which tools were actually invoked — so Raft can only relay the planner's own claim about what it inspected. Status: endpoint shipped; hosted registration is what the public deployment unblocks.

- **Budgets** — I've used Budgets as the hard cost ceiling under a run over 847 conversations. I found having nothing to integrate easy: the ceiling lives on the API key and is enforced server-side, which is the right place. I struggled with granularity, missing cost in `usage`, no pre-flight check and never seeing the rejection, because the only shape is a per-key hard stop while a product needs a per-**run** ceiling, so I built estimate, confirmation ("About $0.07 and 7–19 minutes. Run it?"), checkpoint, pause and resume myself; because `usage` carries no cost field, so Raft prices its own calls from a local table; and because I never provoked the 403, so the pause/resume test exercises Raft's ceiling, not Otari's. The pause machinery earned its keep anyway: on 4 Sep the gateway's authorization service began returning `502 Authorization service unavailable` under any concurrency above ~3 (12 in flight had been clean two hours earlier), and the flagship run paused at 48 of 847 with every judged row saved, then resumed to completion.

- **Code Execution** — I've used Code Execution because the product's hard rule is that no model may count. I found the session model easy: create / exec / delete is a small honest API that let Raft own the Python source, so the code in "Show the work" is literally the string that produced the number. I struggled with availability, getting data **in**, and two competing shapes for one feature, because hosted Otari answers `503 code execution backend is not configured (SANDBOX_BACKEND_URL unset)`; because there is no upload route, so an 847-row table has to be streamed through `exec` as string chunks under the 2 MiB cap; and because the feature exists both as a declared tool and as directly-driven sessions with no guidance on which is authoritative. Aggregation therefore runs in-process on the same source, and the UI names which path executed.

- **Web Search Enablement** — I've used Web Search to explain provider error codes a user has never seen before. I found the declaration easy: one entry in `tools`, identical in shape to code execution. I struggled with having no successful response at all, and therefore with citations, because I never observed the tool return — and a citable source is the entire value of looking something up rather than asking a model to recall it. The local fallback ships a six-code reference table that states outright "no web search was performed". This is the feature I have the least to say about, which is itself the finding.

**Open-weights models:** six roles, six open-weights models, every one with a live request ID in the log — `openai/gpt-oss-120b` (planner), `Qwen/Qwen3-30B-A3B-Instruct-2507` (aspect evaluator), `NousResearch/Hermes-4-405B` (cluster namer, autopsy — replacing the 70B that vanished), `nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B` (trace labeler), `google/gemma-3-27b-it` (span explainer), `meta-llama/Llama-3.3-70B-Instruct` (naming fallback, measured live). `GET /api/settings/preflight` on the public instance reports all six roles reachable against 376 catalog models.

**Other friction, exactly as hit:** reasoning models return `content: null` with `finish_reason: length` when `max_tokens` is small; no `/v1/embeddings` on hosted (404), so embeddings stay local; the sandbox moved from `503 backend not configured` (24 Aug) to sessions that create but `502 code execution backend error` on exec (4 Sep); web search went from silent to `422 Exceeded max_tool_iterations=10` — the first proof the tool runs at all; and the authorization service 502s under burst (measured: 1 in flight 100%, 3 → 82.5%, 4 → 65%, 12 → 12.5% on the evening of 4 Sep, after 12 had been clean at midday), so the concurrency figure any client picks has a shelf life of hours. Nemotron-3-Nano returned a literal quote 1 time in 4; Raft verifies every quote as a substring and drops the rest, so nothing paraphrased reaches the screen.

Raft is fully functional with no Otari credentials configured, and every screen labels which path actually executed — so nothing above is a claim about a path that did not run.
